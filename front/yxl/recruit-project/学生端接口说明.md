# 学生端接口开发说明

## 功能概述

本次开发完成了学生端的两个核心接口：
1. **完善学生信息接口** - 允许学生更新个人信息（不包括学号和姓名等敏感信息）
2. **上传简历接口** - 支持学生上传简历文件到本地服务器

## 接口详情

### 1. 完善学生信息

#### 接口信息
- **路径**: `PUT /stu/completeInfo`
- **认证**: 需要Bearer Token
- **Content-Type**: `application/json`

#### 请求参数

```json
{
  "age": 22,
  "gender": "男",
  "nation": "汉族",
  "major": "计算机科学与技术",
  "degree": "本科",
  "graduationYear": 2025,
  "internship": 2,
  "languages": [
    {
      "language": "英语",
      "level": "六级"
    },
    {
      "language": "日语",
      "level": "N2"
    }
  ],
  "cities": ["北京", "上海"],
  "provinces": ["广东", "江苏"],
  "certificates": [
    {
      "certName": "软考中级软件设计师",
      "level": "中级"
    }
  ],
  "internships": [
    {
      "company": "腾讯",
      "experience": "后端开发实习"
    }
  ],
  "specialities": ["Java", "Python", "MySQL"],
  "jobs": ["后端开发", "全栈开发"]
}
```

#### 响应示例

**成功（200）：**
```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "id": 1,
    "stuId": 2024081101,
    "name": "张三",
    "age": 22,
    "gender": "男",
    "nation": "汉族",
    "major": "计算机科学与技术",
    "degree": "本科",
    "graduationYear": 2025,
    "internship": 2
  }
}
```

**错误响应：**
```json
{
  "code": 42201,
  "message": "年龄超出合理范围",
  "data": null
}
```

#### 安全限制

⚠️ **不允许修改的字段：**
- `id` - 学生ID
- `stuId` - 学号
- `name` - 姓名

这些字段即使在请求中传入也会被忽略，确保敏感信息不被篡改。

#### 业务验证

1. **年龄验证**: 必须在16-60之间
2. **毕业年份验证**: 必须在当前年份-50到当前年份+10之间

#### 数据更新策略

所有关联数据采用**先删除后插入**的策略：
- 语言信息（stu_language）
- 地区信息（stu_region）
- 证书信息（stu_certificate）
- 实习信息（stu_internship）
- 专业技能（stu_speciality）
- 求职意向（stu_job）

### 2. 上传简历

#### 接口信息
- **路径**: `POST /stu/uploadResume`
- **认证**: 需要Bearer Token
- **Content-Type**: `multipart/form-data`

#### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| resumeFile | file | 是 | 简历文件 |

#### 文件限制

- **最大大小**: 10MB
- **支持格式**: 
  - PDF (.pdf)
  - Word (.doc)
  - Word (.docx)

#### 响应示例

**成功（201）：**
```json
{
  "code": 201,
  "message": "简历上传成功",
  "data": {
    "resumeId": 1,
    "resumeName": "2024081101_20251107143025_a1b2c3d4.pdf",
    "resumeUrl": "/api/resume/download/2024081101_20251107143025_a1b2c3d4.pdf"
  }
}
```

**错误响应：**

```json
// 文件大小超限
{
  "code": 41301,
  "message": "文件大小超限，最大支持10MB",
  "data": null
}

// 文件格式不支持
{
  "code": 41501,
  "message": "文件格式不支持，仅支持PDF、DOC、DOCX格式",
  "data": null
}
```

#### 文件命名规则

生成的文件名格式：`{学号}_{时间戳}_{随机字符串}.{扩展名}`

示例：`2024081101_20251107143025_a1b2c3d4.pdf`

#### 存储位置

- **配置路径**: `file.upload.resume-path` (application.yml)
- **默认路径**: `uploads/resume/`
- **完整路径**: 项目根目录/uploads/resume/

#### 数据库记录

简历路径保存在`stu_resume`表中：
```sql
INSERT INTO stu_resume (stu_id, resume) 
VALUES (1, 'uploads/resume/2024081101_20251107143025_a1b2c3d4.pdf');
```

## 技术实现

### 事务管理

两个接口都使用了`@Transactional`注解，确保数据一致性：
```java

```

### 批量操作

使用MyBatis动态SQL实现批量插入，提高性能：
```xml
<foreach collection='list' item='item' separator=','>
  (#{stuId}, #{item.language}, #{item.level})
</foreach>
```

### 文件处理

使用Java NIO进行文件操作：
```java
Files.copy(file.getInputStream(), filePath);
```

### Token验证

通过拦截器从Token中获取用户ID：
```java
Integer userId = (Integer) request.getAttribute("userId");
```

## 数据库变化

### 涉及的表

1. **student** - 学生基本信息
2. **stu_language** - 语言信息
3. **stu_region** - 地区信息
4. **stu_certificate** - 证书信息
5. **stu_internship** - 实习信息
6. **stu_speciality** - 专业技能
7. **stu_job** - 求职意向
8. **stu_resume** - 简历文件

### 数据流转

```
请求数据 → StudentCompleteInfoDTO
    ↓
解析并验证
    ↓
更新student表（基本信息）
    ↓
删除旧关联数据
    ↓
批量插入新关联数据
    ↓
返回更新后的student对象
```

## 注意事项

### 1. 文件存储目录

确保应用有权限创建和写入`uploads/resume/`目录：
```bash
mkdir -p uploads/resume
chmod 755 uploads/resume
```

### 2. 敏感字段保护

代码中明确**不允许**修改的字段：
- 学号 (stuId)
- 姓名 (name)  
- 学生ID (id)

即使前端传入这些字段，后端也会忽略。

### 3. 批量操作限制

建议单次更新的关联数据不超过100条，避免性能问题。

### 4. 文件清理

建议定期清理过期的简历文件，可以通过定时任务实现。

### 5. 并发控制

当前实现未添加乐观锁，高并发场景下可能需要添加版本号字段。
